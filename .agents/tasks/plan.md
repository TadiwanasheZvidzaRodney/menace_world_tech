# Implementation Plan

Implementation decisions: keep the site Astro-only with typed Astro components, plain TypeScript, and CSS so the static build has no framework runtime or new dependency surface. Put reusable copy and exact contact/pricing facts in typed data modules, use one imported global token layer plus scoped component styles, and create all brand/showcase artwork locally as SVG/CSS because the scaffold contains no uploaded brand assets. Configure an optional `SITE_URL` rather than inventing a domain; metadata that needs an absolute URL will be emitted only when that deployment value exists.

- [ ] 1. Establish the static configuration, documented brand system, typed content model, canonical contact helpers, and original local brand assets.
      Set `output: 'static'` explicitly and accept an optional `SITE_URL` in `astro.config.mjs`. Define the requested base/raised/panel colors (`#05030A`, `#0B0712`, `#100A1C`), violet/magenta/cyan accents (`#7C21F5`, `#F20ECF`, `#12DDF3`), text/muted colors (`#F7F5FF`, `#AAA3BA`), a named 4/8px spacing scale, geometric system display and readable body stacks, angular/small radii, borders, shadows/glows, content widths, focus states, responsive breakpoints, overflow guards, and reduced-motion behavior in the global CSS. Model navigation, metadata, capability strip, Audit → Build → Launch → Optimize process, values, phone/WhatsApp constants, all eight services, the six featured-home services, package tiers, add-ons, and FAQs in typed data; keep outcomes framed as strategy, execution, optimization, and transparent reporting rather than guarantees. Add a reusable WhatsApp URL/message helper fixed to `263783980802` and original angular M/up-arrow and social-card SVGs; replace the Astro favicon and remove the stale Astro `.ico` rather than linking a mismatched binary.
